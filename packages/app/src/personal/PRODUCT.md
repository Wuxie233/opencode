# Personal UI Product

## Register

product

## Users

One operator uses OpenCode throughout the day from a remote web browser and occasionally from the shared desktop application. The primary job is to manage several projects and sessions, follow agent activity, inspect tool and file changes, answer blocking requests, and continue work without changing applications.

## Product Purpose

Provide a complete personal OpenCode interface over the native application state and capabilities. Success means the Personal UI can replace the upstream Web presentation for daily work without duplicating or weakening OpenCode's session, message, tool, file, review, terminal, permission, model, provider, MCP, or persistence behavior.

## Brand Personality

Quiet, precise, dependable. The interface should feel like a compact professional operations surface, not a marketing page, terminal imitation, or decorative AI dashboard.

## Anti-references

- Loose card galleries that reduce visible work and hide relationships.
- Oversized metrics, decorative gradients, glass panels, and novelty motion.
- A paper-and-ink clone of cc-haha or use of its seal, mascot, screenshots, or other brand assets.
- A second client state model that drifts from native OpenCode behavior.
- Desktop density achieved by sacrificing mobile touch targets or keyboard access.

## Design Principles

- Keep native behavior authoritative and change presentation at a narrow shell seam.
- Keep projects, sessions, conversation, activity, review, and terminal context visible without page hopping.
- Use compact density for scanning while preserving readable message content.
- Put blocking questions, permissions, errors, retries, and active work ahead of passive history.
- Keep the upstream New Layout as the behavior foundation while Personal UI owns the daily presentation.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Preserve complete keyboard operation, visible focus, non-color state cues, browser zoom, reduced-motion behavior, and 44px mobile touch targets. Desktop controls may be visually compact but must remain reliably operable.
